# 重构说明：旧版问题与对应改动

本文记录 2026-09 系统性重构前代码中确认存在的问题，以及新版的处理方式，方便对照审阅。
"旧版"指重构提交之前的版本，可在 git 历史中查看（如 `git show <重构前提交>:src/engine/gameEngine.ts`）。

---

## 1. 规则数据与官方不符

| 问题 | 旧版 | 新版 |
| --- | --- | --- |
| 版图 | 16 格需 1–4 位投资者，分红 1–7 份与投资者数无关（例：第 3 格需 A、D、E 只给 1 份，第 16 格给 7 份） | 依官方版图：每格 2–5 位投资者，分红 = 投资者数 + 1；支持"必需组 + 可选池""双可选池""六选五"等真实结构（`DealGroup[]`） |
| 景气牌 | $1M→$12M 递增，单笔最高 $84M；终局骰面 6 / 5-6 / 4-6 … | 官方：$2M×4、$3M×4、$4M×4、$5M×3，单笔最高 $30M；终局骰面 1 / 1-2 / 1-3 / 1-4 / 1-5 / 自动 |
| 家族 | 文档写 Goldman 等英文名，代码另有中文名 | 文档与代码统一为同一套名称与颜色 |
| 规则文档 `新.md` | 表格与实现互相矛盾，且大量段落重复 | 重写为 `docs/rules.md`，表格直接对照 `config.ts`；新增"数字版实现约定"一节 |

## 2. 引擎与状态

| 问题 | 旧版 | 新版 |
| --- | --- | --- |
| 随机不可复现 | `Math.random()` 洗牌 / 掷骰，AI 内也用 | 全部随机来自 `state.rng`（mulberry32），开局可填种子；一局 = 种子 + 动作序列 |
| reducer 不纯 | 日志 / 台词 / 交易记录带 `Date.now()`，id 用模块级计数器，读档后 id 冲突 | 所有 id 来自 `state.nextId`；状态中不含时间戳 |
| 动作无行动者 | `CHOOSE_DEAL / CLOSE_DEAL / FAIL_DEAL / ROLL_DIE …` 无 `playerId`，`FAIL_DEAL` 任何人任何时候可派发 | 每个 `PlayerAction` 都带 `playerId`；`isLegal` 校验行动者与阶段 |
| 三套规则口径 | reducer 内联校验、`getLegalActions`、`validateAction` 各写一遍且互有分歧（历史上多次因此冻结） | `validator.ts` 唯一口径：`getLegalActions` 生成候选，`isLegal` 判定；reducer 第一步就是 `isLegal` |
| reducer 校验漏洞 | 招募 `cardIds:[5,5,5]` 用 1 张牌即可通过；旅行牌不校验目标是否在场，可对已打飞代表再弃一次牌（复制卡牌） | `distinctCardsOfType` 要求 3 张不同招募牌；旅行目标必须是桌上未失效代表（`travelTargets`） |
| 界面瞬态入状态 | `thinkingPlayerId` / `SET_AI_THINKING` 写进 `GameState` 且不推进版本，每次 AI 决策多写两次存档 | "思考中"是 `GameSession` 快照的 `thinkingId`；`GameState` 只含游戏事实 |
| 引擎生产文案 | reducer 内拼接中文日志字符串（`log: string[]`），UI / AI 提示词 / 测试都只能对字符串做模糊匹配，换措辞即破坏一切 | 引擎只 `emit` 结构化 `GameEvent`；`text/narrate.ts` 把事件讲成文字，`text/labels.ts` 把动作 / 卡牌 / 方案 / 错误变成文字，UI 与 LLM 提示词共用；测试断言事件而非文案 |
| 台词是独立动作 | `AI_SPEECH` 动作绕过阶段与次数限制，不携带报价，需要 UI 与 AI 分别派发 | 任何 `PlayerAction` 都可附带 `say`，引擎统一落成 `SPEECH` 事件与座位气泡；`PASS_REACTION` 的 `say` 被丢弃以免泄露手牌 |
| 校验错误是字符串 | `validateOfferShape` 返回中文字符串，界面直接显示、引擎按是否为空判定 | 返回结构化 `OfferError`，界面用 `describeOfferError` 渲染 |
| 派生冗余 | `isCurrentBoss`、`playerCount`、`winnerId`、投资者与代表两处 `isTravelled` 需手工同步 | 只存事实，派生量通过 `rules.ts` 查询 |
| 拒绝无反馈 | 拒绝动作时先写日志再 `return state`，日志随克隆丢弃 | 不合法动作不会到达 reducer 主体；界面按钮由合法动作驱动，不存在"能点但被拒" |
| 手牌上限死代码 | 家族卡回手后设 `HAND_LIMIT_CHECK`，随后被无条件覆盖为 `TURN_START`，玩家可长期持 >12 张 | 手牌上限在抽牌后立即处理；家族卡回手不会超限（打出时已从手牌移出）；仿真断言手牌 ≤ 12 |
| 开局校验 | 人数不在 3–6 时把投资者分给不存在的玩家 | `createInitialState` 夹到 3–6；4/5 人局起始玩家跳过公共区投资者 |

## 3. 谈判流程

| 问题 | 旧版 | 新版 |
| --- | --- | --- |
| Boss 让出优先权即受罚 | 全员各跳过一次（含 Boss 想听要价）就判僵局流局 | 跳过一整轮只记一次"停滞"，连续两轮才流局；Boss 提案 / 成交不依赖跳过计数 |
| 成交被任意打断 | 任何人一句喊话就重置 `bossReadyToClose`，Boss 需再等一圈；最多可被取消 3×(n−1) 次 | `CLOSE_DEAL` 进入独立的 `CLOSING` 阶段，其他人只能出干扰牌或放行；被阻止的牌不打断倒计时 |
| 出借确认 | 拒绝后同一阵容原样重提，Boss 唯一杠杆是加价，直到耗尽次数流局；提案次数还被对手的旅行牌消耗 | `OFFER_RESPONSE` 逐个应答，拒绝可附反报价并记为新要价；Boss 可重提、换用竞争代表或放弃；方案作废不扣次数，只有主动提案计数（5 次） |
| 结算兜底改代表不改分成 | 结算时用"最便宜代表"覆盖 Boss 的手选阵容，但沿用旧 payout，新代表持有者分文未得 | 只结算全员同意且仍有效的方案；代表被打飞 / 易主时方案立即作废并提示重提 |
| 方案可夹带无关家族 | 合约可含与本格无关的代表，其持有者由此获得否决权 | `validateOfferShape` 拒绝无关家族、重复家族、多选 |
| Boss 自我报价 | Boss 可对自己的代表报价，易主后变成对新 Boss 的真实要价 | 报价语义按"是否有相关代表"判定；Boss 易主时方案 / 次数 / 停滞计数清零，桌面代表与失效状态继承 |
| 出牌限本人回合 | 旅行 / 老板牌只能在自己的谈判回合打 | 谈判阶段按轮转出牌；成交倒计时每人有独立的最后出牌机会 |
| 反应窗口泄露手牌 | 只询问持有阻止牌的玩家，窗口是否出现即暴露"有人持阻止牌" | 按座位依次询问所有其他玩家；无阻止牌者只能放行（人类自动放行，停顿同长）；界面不显示当前被询问者 |
| 下一回合起点 | 以最终 Boss 为基准，易主后座位被跳过或重复 | 规则即"最终 Boss 左手边"，与官方一致；文档与实现明确写出 |

## 4. 卡牌与现金守恒

| 问题 | 旧版 | 新版 |
| --- | --- | --- |
| 无守恒断言 | 仿真只检查"不冻结、有限步结束" | 每步断言 98 张守恒且 id 唯一、现金 = 成交总额、无负现金、手牌 ≤ 12、已关闭格 = 成交数、标记在未关闭格 |
| 抽牌静默少抽 | 两堆皆空时 `if (card)` 跳过 | 抽牌堆空则洗弃牌堆；两堆皆空才停止（98 张牌下几乎不可能） |
| 弃牌后仍超限整体回滚 | 日志已写却回滚 | `DISCARD` 的 `cardIds` 数量必须恰好等于超出张数（`isLegal`） |
| 分成截断静默 | 超额按顺序先到先得 | 提案时即校验总额 ≤ 总金额；结算的截断仅为防御 |

## 5. AI 与前端管线

| 问题 | 旧版 | 新版 |
| --- | --- | --- |
| LLM 直接生成合约 | 大量非法结构（不存在的代表、超额、无关家族），失败后引擎拒绝、界面无反馈 | 按编号选择合法动作，只允许 `demand / payouts / cardIds` 微调，且必须通过 `isLegal`（`llmPolicy.ts`） |
| AI 管线与 React 纠缠 | `useGame` 里 effect + ref + 300ms 看门狗计时器驱动 AI；StrictMode / HMR 下 `aiFlightRef` 去重导致 AI 永不行动；Node 仿真只能绕过这条管线，等于没测到真正跑游戏的代码 | 框架无关的 `GameSession`（`game/session.ts`）：状态一变就调度、`AbortSignal` 作废过期决策、非法 / 异常策略回退到启发式；进度靠"合法动作必被接受、接受必推进版本"的结构保证而不靠计时器；浏览器与 Node 仿真跑同一份运行时，`tests/session.test.ts` 直接测它 |
| AI 没有统一接口 | LLM 与启发式各有函数签名，兜底逻辑散在调用方 | `Policy` 接口 + `withFallback` 组合子；`heuristicPolicy` 永远给出合法动作，作为最终兜底 |
| 免费发言 | `ADD_SPEECH_BUBBLE` 不受阶段与次数限制 | 台词随动作附带（`say`），`SPEAK` 受每人 4 次限制（`MAX_SPEECHES_PER_PLAYER`），其他动作的台词不计次也不携带报价 |
| 存档无版本 | 靠字段存在性猜旧档 | `saveVersion` 不匹配直接丢弃 |
| 界面自带规则 | 组件内判断能否出牌 / 能否成交 | 按钮完全由 `getLegalActions` 驱动；方案编辑器用 `validateOfferShape` 实时校验 |
| 弹层被裁切、结果卡遮挡 | 手牌弹层在横向滚动容器内被 `overflow` 裁掉；终局结果卡无法关闭 | 弹层挂在手牌容器外并随牌定位、点击外部关闭；结果卡可关闭复盘并随时重新打开 |
| 离开对局 AI 仍在跑 | 返回首页后 effect 仍可能派发动作并覆盖存档 | `leave()` 销毁 session，之后不再推进、不再接受动作 |

## 6. 测试与文档

| 问题 | 旧版 | 新版 |
| --- | --- | --- |
| 没有单元测试 | 只有"跑几百局不冻结"的仿真 | vitest 66 个用例：静态数据对照官方规则、规则场景逐条验证、合法动作性质测试、运行时行为、LLM 协议解析、整局仿真回归；`npm test` 一键运行 |
| 仿真种子无效 | `seed` 只用于报错文案，随机未播种 | 种子真正驱动 RNG，`npm run simulate -- 4 7 random` 可精确复现；仿真逻辑抽到 `sim/harness.ts` 供 CLI 与测试共用 |
| README 与实现不一致 | 宣称 reducer 复用 validator、反应窗口脱敏等，实际并非如此 | README 只保留概览与索引；细节分到 `docs/rules.md`、`docs/architecture.md`、`docs/ai.md`、`docs/development.md`，均对照代码写成；`新.md` 删除 |

## 验证方式

```bash
npm run check                     # typecheck → vitest → 400 局仿真
npm run build
```

浏览器内已手工走通：开局放标记 → 发起交易 → 打家族卡报价 → 提案 / 应答 / 反报价 → 宣布成交 → 倒计时出牌 / 放行 → 结算 → 手牌上限招募 → 读档续局 → 终局结果复盘 → 返回首页后电脑停止行动。
