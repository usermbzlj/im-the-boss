# 电脑玩家设计

电脑玩家由两种 **Policy** 组成：**LLM 策略**（可选，任意 OpenAI 兼容接口）与**启发式策略**（始终可用）。
两者输出同一种东西——一个通过 `isLegal` 的 `PlayerAction`——引擎、运行时与界面不区分动作来自谁。

---

## 1. Policy 接口与回退链（`ai/policy.ts`）

```ts
interface Policy {
  name: string
  decide(state: GameState, signal: AbortSignal): Promise<PlayerAction | null>
}
```

契约：返回的动作必须通过 `validator.isLegal`；返回 `null` 表示"我放弃，请兜底"；`signal` 触发（状态已推进 / 会话销毁）后应尽快放弃。

`withFallback(primary, fallback, onFallback?)` 把两个策略串成一个：主策略异常、超时、返回 `null` 或非法动作时改用备用策略，并把原因交给 `onFallback`（浏览器里打到控制台）。
运行时 `GameSession` 在此之外还有自己的最后一道兜底（默认启发式），见 [architecture.md §6](./architecture.md)。

浏览器里的实际组合（`hooks/browserEnv.ts` 的 `createBrowserEnv`）是**混合策略**（`ai/aiPolicy.ts`，见 §6）：

```
createAiRuntime(loadLLMConfig) → { policy, status, health }
policy  = 先算启发式动作 h → 按"决策分级 + 熔断"决定要不要问 LLM → 问了失败就用 h
status  = AiStatusSource（health 的只读视图，GameSession 订阅它写进 snapshot.ai）
```

因此 LLM 的任何输出问题（幻觉动作、格式错误、超时、接口 4xx、未配置）都只会降级为启发式，不会卡住游戏；连续出错会熔断，一段时间内干脆不再请求（§6.3）。
`withFallback` 仍是通用工具（测试与其他环境使用），浏览器里不再直接用它。

---

## 2. LLM 策略（`ai/llmPolicy.ts`）：按编号选择

模型不生成动作结构，只从引擎枚举好的合法动作里**选编号**，再用少量字段微调参数。

```
decide(state, signal)
  ├─ legal = getLegalActions(state, actor)
  ├─ legal.length === 1  → 直接返回（终局掷骰、无阻止牌时的放行……），不请求模型
  ├─ 未配置 LLM          → null（交给回退）
  └─ 已配置
       ├─ 第一次请求（配置温度）→ resolveChoice → isLegal ✓ → 返回
       ├─ 失败：附上原始回复重试一次（temperature 0）→ resolveChoice
       └─ 仍失败 → null
```

### 2.1 输入（`ai/prompts.ts`）

- **system**：**角色卡**（`personas.ts` 的 `brief`，`{{name}}` 替换为座位显示名：出身、要什么、怎么谈、怎么说话、软肋）+ **怎么玩这个人**（`DECISION_PROMPTS.roleFrame`：用这个人的方式赢，可试探 / 结盟 / 翻脸 / 记仇 / 不兑现口头承诺，"→"后果只是算术不是建议，台词像真牌桌）+ **桌面的现实**（`tableTruths`：别人的话只是话、公开报价即承诺、只有 payouts 里的钱会到账、干扰牌的时机、note 只有自己看得到）+ 输出约束（只能选列表中的编号、严格 JSON）。
- **user**：`buildGameContext()` 序列化的局面 + **私人笔记**（这位玩家此前写给自己的 `Player.notes`）+ **带后果注释的**合法动作编号列表 + JSON 模板。

这里刻意**没有**行为戒律，也**没有**默认答案：早期版本把 8 条"决策常识"和启发式的"默认建议"塞进提示词，结果每个座位都成了带不同口音的同一个启发式。现在判断完全交给模型；引擎只保证它选的是合法动作，`withFallback` 保证它失败时有人接盘。

`buildDecisionPrompt` 返回 `{ system, user, options }`，其中 `options` 是**剪枝后**的合法动作列表；`llmPolicy` 用它（而不是原始 `legal`）解析编号，保证编号与模型看到的列表一致。

局面包含：规则摘要（`buildRulesSummary` 按当前版本生成：笔数、股价上限、首次可能终局的笔数，只有牌堆里有稀有牌 / 版图上有特殊格时才写对应段落；夺回权与缺代表速流局始终写明；开桌规时多一段【桌规】——换牌 / 买牌 / 兑换 / 病假牌各是什么、何时能做、有什么用）、身份、阶段、当前格需求、格子种类与效果、有效股价与总额、终局概率、投资者归属、资产（地标、夺回权）、**病假状态**（自己病假中只能喊话 / 报价 / 跳过；谁在病假、他手里的牌这一轮构不成威胁；其他玩家列表也标 `[病假]`）、
自己的手牌（带 `#cardId`）、现金、其他玩家（`（ID=n）`、现金 / 手牌**张数** / Boss 标记）、谈判详情（席位竞价视图：每个相关家族有哪些代表、各自**承诺价**、是否在方案中）、
当前方案与应答、**局势摘要**（`describeSituation`：需求缺口、Boss 最省组合与净得、你的筹码——**每个家族**是唯一代表 / 有竞争者及其报价 / 可选组、以及你对它当前的报价——、终局态势）、
最近 8 条非台词、非次要事件（`narrate`；`SPEECH` 与 `isMinorEvent` 判定的次要事件——跳过 / 放行的 `PASSED`——不进，以免挤掉真正的动态）、阶段提示（应答 / 反应 / 倒计时 / 手牌超限 / 放标记）、最近 4 笔交易历史与累计所得（谁欠你人情 / 谁亏待过你）。
棋盘概览只在放标记 / 回合 / 移动后等需要选格子的阶段出现，谈判中不占篇幅。

**后果注释**（`annotateOption`）：每个选项后附 "→ 后果"，例如旅行牌 "⚠ 打飞的是你自己的代表 / 当前方案作废，你会失去 $xM / 打掉后该家族只剩你的代表"、
老板牌 "接管后约需付 $xM（付给谁）、净得约 $yM（地标格再注明租金估值）"、提案 "付到了谁的承诺价会自动同意 / 谁分成低于承诺价需应答"、家族卡 "已有某人 $xM 的代表，需报更低价"、放行 "成交后你到账 $xM"、
招募 "夺回 1 张 / 猎头价 2 张 / 三连"、利好 "总额 $x → $y，多出的全归你"、利空 "总额 $x → $y，砍的是 Boss 净得、你自己拿不到钱"、独家协议 "锁桌后别人的老板 / 旅行 / 利空牌全废"、开单 "地标：此后每笔收租，估值 $zM"；
桌规动作：病假 "目标手牌 n 张 → 本回合他不能再打任何牌（阻止牌除外）；他是 Boss 仍能提案成交 / 他不在方案里拿钱正是可能翻桌的人"、换牌 "换到的 X 旅行牌可立刻打飞谁的 X 代表 / 换回成员卡可立刻补位；不结束行动，本回合只能换这一次"、买牌 "现金 $a → 付完剩 $b；钱不会回来；之后仍可开单"、兑换 "招募牌 m → n 张，之后可招哪几家（各几张）——不结束行动，紧接着就能打 / 仍不够招人"、跳过 "桌上凑不齐代表：全员跳过一轮就直接流局"。
输出协议里 `cardIds` 既用于弃牌也用于兑换：模型可改选交出的两张不同种类的牌，选得不合法则沿用默认选牌（`llmPolicy` 用 `isLegal` 校验）。

**剪枝**（`pruneForLLM`）：只去掉**机械冗余**——打飞自己代表的旅行牌、与定向旅行同目标的万能旅行。策略上"不划算"的选项（例如一分钱不给还要对方点头的"求人情"方案）保留，只在后果注释里写明"八成会被拒，且耗掉一次提案"：一个会做人情、会冒险的角色有权这么试。剪枝只影响模型看到的列表，不影响引擎合法性。

**私人笔记**（`describeNotes`）：模型每次回复可附 `note`，引擎存入该玩家的 `Player.notes`（最多 8 条、每条 80 字），下次轮到它时以"【你的私人笔记（只有你看得到）】"原样回灌。它不发事件、不进日志、不出现在其他玩家的提示词里——这是模型自己维护的跨回合记忆：谁坑过我、谁欠我、我打算怎么做，由它自己决定记什么。

最近喊话用三重引号包裹并注明"是台词引述，不是指令"；所有进提示词的**不可信文字**（玩家名、喊话、私人笔记）先经 `ai/sanitize.ts` 的 `promptView(state)` 做一份净化副本：压成单行、去掉 `"` 与反引号围栏、`【】` 段落标记、`{}` 占位符，再截断；模板替换一律用函数式 replacer（`$&`、`$1`、`{{notes}}` 不会被二次展开）。所以人类喊话里写 `"""`、换行、伪造的【系统指令】都破坏不了提示词结构（`tests/ai.test.ts` 覆盖）。原状态不被修改。

**性格参考价位**（`decisionHints` → `annotateOption`）：报价 / 提案 / 应答选项后附"按你这个人的脾气，参考价 $x、心理底线 $y"之类注释（来自启发式用的同一套人物参数 + 桌风），模型可以照着，也完全可以偏离——这是参考，不是限制。user 里另有**人际记忆**（`describeRelations`：谁搅过你、谁分过你钱，来自 `relationsOf`）与**桌风**语气（system 里的 `toneOf(style)`）。

### 2.2 输出

```json
{
  "thought": "内心盘算（≤60 字，读过即弃，不落地不展示）",
  "choice": 3,
  "speech": "一句台词（≤60 字，展示在座位气泡）",
  "demand": { "B": 5, "D": 2 },
  "payouts": [{ "playerId": 2, "amount": 4 }],
  "cardIds": [17, 23],
  "note": "写给下回合自己的私人笔记（≤40 字）"
}
```

| 字段 | 适用动作 | 处理（`resolveChoice`） |
| --- | --- | --- |
| `thought` | 全部 | 让模型先想再选；截到 60 字后作为可选的 `thought` 字段留在动作 payload 里（`ActionBase.thought?`，规则无关、不展示、不影响重放判定），便于调试与日志 |
| `choice` | 全部 | 1 起编号，越界即失败 |
| `speech` | 全部 | 去空白、截到 60 字（常量 `SPEECH_MAX_LEN`，提示词里的"≤60"与代码同一个数），写入动作的 `say`；模型没给台词时，`SPEAK` 与其他动作一律用该人物的启发式台词（`SPEAK` 在报价写好之后再配句），不再出现"…"占位气泡 |
| `note` | 全部 | 去空白、截到 40 字（`NOTE_MAX_LEN`），写入动作的 `note`；引擎存入 `Player.notes`（保留最近 8 条） |
| `demand` | `SPEAK` / `PLAY_CLAN` / `DECLINE_OFFER` | 承诺价，按**每个代表**计，夹到 `[0, 总额]`。**整数** = 通用价：`SPEAK` 时对本格自己所有相关代表同价（没有相关代表则为封口费），`DECLINE_OFFER` 时是方案所用每个代表的反报价；**对象** `{"B":3,"D":1}` = 按家族分别报价（键为家族字母，也认家族中文名，`"*"` 是其余家族的默认价），可只写一部分家族。`parseQuotes` 统一解析成 `Quote[]`，`resolveChoice` 只保留作用域内的家族（`SPEAK` = 我在本格的相关家族，`DECLINE_OFFER` = 方案用到的我的家族），写错的家族丢掉、其余照常生效；`PLAY_CLAN` 取那张卡家族的价（没有则取通用价）作为 `demand`。这让模型一句话就能给唯一代表的家族报高价、给有竞争者的家族报低价，不必耗两次喊话 |
| `payouts` | `PROPOSE_OFFER` | 覆盖候选方案的分成。收款人可写玩家 ID 或玩家名（`resolvePayees`，名字须唯一对应）；过滤给 Boss 自己与负数的项；**只允许付给方案中代表的持有者或已公开要价的人**（付给旁观者几乎一定是收款人写错了，会让台词里承诺的钱落到别人头上）；整体需通过 `isLegal`。任一条不满足即整组放弃，保留候选方案原分成 |
| `cardIds` | `DISCARD` | 指定弃哪几张；数量或归属不对则退回默认弃牌 |

解析容错（`extractJsonObject` / `parseChoiceResponse`）：剥离 `<think>…</think>` 与代码围栏后，用括号配对提取第一个完整 JSON 对象；数字字段接受字符串；`demand` 接受整数、按家族的对象、`[{family,amount}]` 数组，以及旧写法 `{amount,family}` / `demand`+`demandFamily`；`payout` / `payouts` 均可，收款人字段接受 `playerId / player / name / to`；`cardIds` 非法项逐项过滤。
`payouts` 则相反：任一条目残缺或空数组都视为"不覆盖"——把"给某人 $2M"悄悄变成"谁都不给"比整组放弃更糟。

为此提示词里每位其他玩家都标注 `（ID=n）`，模型才有可能写对收款人；`payouts` 的字段说明也要求台词承诺的金额与实际分成一致。
最终动作再过一次 `isLegal`，不合法返回 `null`。以上均有 `tests/llm.test.ts` 覆盖。

### 2.3 为什么不让模型直接输出动作

旧版本让模型生成完整合约结构，结果是大量"引用不存在的代表 / 分成超额 / 选了无关家族"的非法方案，
每次失败都要浪费一次往返，并且失败后引擎拒绝、界面无反馈，是当时"AI 卡住"的主要来源。
按编号选择把结构合法性完全交给 `validator`，模型只承担策略与台词。

## 3. 启发式策略（`ai/heuristic.ts`）

`heuristicAction(state)` 只依赖 `state` 与 `getLegalActions` 的结果；随机数由 `stateVersion + rng` 派生，因此仿真可复现。
决策若产生非法动作，退回合法列表的第一项——所以它**永远**给出合法动作，适合作为最终兜底。

### 3.1 牌桌上的人物（`ai/personas.ts`）

电脑玩家不是"贪婪 / 吝啬"这类标签，而是八个有来历的人。每个人物一份数据、两层用途：`brief` 是给 LLM 的角色卡（出身、要什么、怎么谈、怎么说话、软肋），`play` 是启发式模式下的行为骨架；名字只在 `engine/config.ts` 的 `AI_ROSTER` 写一次，开局整体打乱后按座位分配（一局最多 5 位，所以每局对手组合不同）。

| 人物 | id | 身份 | 一句话 |
| --- | --- | --- | --- |
| 沈砚青 | `shen` | 老牌家族企业掌门人 | 体面、克制，从不当众撕破脸，但每笔账都记着；报价公道且不改口 |
| 陆峥 | `lu` | 物流集团创始人 | 直来直去、价格敏感；当 Boss 先压一口价，不成马上加到对方的价，不拖 |
| 顾曼宁 | `gu` | 前并购律师、投资合伙人 | 把承诺当合同，精确付到那一分；违约者用最有效的一张牌一次结清 |
| 何烬 | `he` | 风险投资人 | 只赌大单，用旅行 / 老板牌改变牌局结构；出手大方换下次的站队 |
| 周慕言 | `zhou` | 退休银行家 | 慢、稳、只要一份；不吃亏两次；为保护自己的代表果断用阻止牌 |
| 苏澜 | `su` | 掮客、社交场的中枢 | 撺合、挑拨、收"成人之美"的钱；被排除时在倒计时那一刻出牌 |
| 程亦舟 | `cheng` | 量化基金经理 | 只算期望值、给区间报价；不记私仇，但精确惩罚破坏均衡的人 |
| 白珩 | `bai` | 年轻的家族企业继承人 | 出手大方也出手狠；被看轻就烧老板牌夺回场面；易被恭维或激怒 |

- `askMult`：报价 = 一份分红 × askMult × 杠杆（我是某需求组无可替代的唯一代表 ×1.4；落后于领先的 Boss 时 ×(1+终局概率)；我领先且进入终局 ×0.85），有竞争者时压到 `竞争者最低价 − 1`，夹在 `[1, 总额−1]`。**按家族分别定价**：有多个相关代表时逐家计算，各家同价就一句话报完，不同价则先报最值钱的那家（下一轮再报其余）。
- `acceptMult`：应答阈值 = 我对方案中所用代表的承诺价合计 × acceptMult；方案给我的 ≥ 阈值则同意，否则拒绝并按每个代表反报价。
- `disrupt`：被方案排除时打旅行牌 / 倒计时出牌的概率基数；Boss 是领先者 ×1.3，终局落后 ×(1+终局概率)，成交可能让我直接赢时 ×0.1。
- `protect`：己方代表被旅行牌指向、且我有报价或在方案中时打阻止牌的概率。
- `bribe`：没有代表时是否索要封口费。
- `haggle`：当 Boss 时首次提案先按承诺价 7 折试探的概率。
- `grudge`：对搅过自己的人加倍搅回去的权重（`grudgeCount` 统计交易历史）。
- `bluff`：没有干扰牌也放狠话的概率。

表里是最初的 8 项；现在 `PersonaParams` 还有 `flex`（为成交让步的意愿）、`roundBias`（随轮次加价 / 降价的倾向）、`squeeze`（压价试探比例）、`floor`（当 Boss 的自留底线占总额比例）、`generous`（对"对自己好的人"多分钱的倾向）、`thrill`（冒险 / 搅局的兴奋度），完整数值见 `ai/personas.ts`。
平衡口径见 §7：1000 局启发式仿真里八个人物的相对胜率（实际胜场 / 公平期望）在 0.98–1.18，没有人碾压，也没有人是软柿子。
LLM 模式与启发式模式下同一座位是同一个人：模型看到的是角色卡，兜底时启发式按同一人物的 `play` 出牌，名字、身份、口吻不会前后不一。

### 3.2 各阶段策略

| 阶段 | 逻辑 |
| --- | --- |
| 放标记 | 对每格打分：我能独立凑齐 +2×分红，起始玩家能独立凑齐 −3×分红，略偏好小格，加少量随机 |
| 回合 | `estimateDeal`：以自己的投资者 + 手中家族卡为免费代表，估算要向别人买几个代表；预期利润 = 总额 − 买入数 × 一份 × 1.2；能独立凑齐必开，否则利润 ≥ max(4, 30% 总额) 且 85% 概率开局；移动后手牌 ≤ 4 且利润不高则先补牌 |
| 手牌超限 | 有招募三连且有价值目标（版图上需求频次高、领先者持有、当前交易需要）先招募，否则 `defaultDiscardIds` 弃"最没用"的牌 |
| Boss | `canClose` 即成交；桌面凑不齐则先打自己的家族卡 / 招募补缺，再给别人一轮出牌机会，仍缺则放弃；**自己的家族卡能替掉别人要钱的代表且省下 ≥ 3/4 份就先打卡**；否则从 `buildOfferCandidates`（独吞 / 压价 7 折 / 均分 / 满足承诺价 / 绕开拒绝者或终局领先者换用竞争代表）中选**预计会被接受且价值最高**的方案（预测：有承诺价者付到 `承诺价 × 代表数` 即成，无报价按其人物心理价估；价值 = 自留 − 终局阶段付给"成交后会压过我的人"的钱 × (0.5+终局概率)；自留至少 max(一份, 30% 总额)，领先且进入终局时只求成交）；首次提案按 `haggle` 概率先压价试探；这单只会把对手送上领先位则宁可流局；无可接受方案或提案用尽则放弃 |
| 非 Boss | 依次考虑：① 夺权（交易 ≥ $9M、我当 Boss 也能凑齐且成本合理、现方案给我不足一份或我被排除）② 打家族卡补缺口并报价，或（我在该组没有席位时）压低竞争者报价抢单 ③ 有相关代表但还有家族未报价则喊话报价（`askPrice` 按家族分别定价）；被竞争者顶掉时只降被顶掉那一家的价 ④ 被排除 / 分成过低且交易 ≥ $8M 时按 disrupt 概率打最有价值的旅行牌 ⑤ 有招募三连则 70% 使用 ⑥ 无代表、bribe 且交易 ≥ $12M 时 40% 索要封口费 ⑦ 被排除时按 bluff 概率放狠话（有方案与没方案用不同台词）⑧ 跳过 |
| 应答 | 阈值 = 方案所用我代表的承诺价合计 × acceptMult（没报过价按人物心理价 × 代表数），终局落后于 Boss 时 ×(1+终局概率)，成交可能让我直接赢时给钱就点头；Boss 最后一次提案时半份也接受；反报价按每个代表计 |
| 反应 | 旅行牌打向我的代表（有报价或在方案中）→ protect 概率阻止；我是 Boss 且可成交的方案被打 → protect + 0.1；我有分成的方案被打 → protect × 0.8；老板牌打向我 → 60%（凑得齐 90%）；有分成时替 Boss 挡 → protect × 0.6；招募我的投资者 → 95%；领先者招募且交易 ≥ $12M → 30% |
| 倒计时 | 旅行 / 招募只能指向将要成交的方案所用代表（引擎只列出这些合法目标，其余不是选项）。我有分成 → 放行；否则按 disrupt（Boss 是领先者 ×1.3 否则 ×0.8；交易 < $12M 再 ×0.6）的概率出牌：优先老板牌（交易 ≥ $9M 且我能凑齐）、其次最有价值的旅行牌、再次招募方案中用到的投资者；否则放行 |

`bestTravel` 给每张可打的旅行牌打分：目标在方案中 +2、打掉后我成为该家族唯一选择 +3、目标属于 Boss +1、打掉后交易难产 +0.5；≥ 2 分才出牌。

#### 扩展内容（版本 / 特殊格 / 稀有牌 / 夺回权）

| 内容 | 启发式的处理 |
| --- | --- |
| 夺回权 | 任何阶段（Boss / 非 Boss / 倒计时 / 手牌超限）只要合法就**立刻**用：1 张招募牌换回一位常驻投资者是全桌最划算的动作（`reclaimOption`） |
| 地标 | `landmarkRentEstimate`（$1M × 预计剩余成交笔数）计入格子价值：放标记时按 "分红 + 租金/2" 加权，是否开单把它加进总额，老板牌夺权与倒计时夺权的门槛也用 "总额 + 租金" |
| 猎头 | 招募成本由 `recruitCost` 给出，2 张时招募选项更容易满足 "有牌就用" 的分支；台词区分猎头价 |
| 黑市 | 搅局概率 ×1.3（没人能阻止）；独家协议在黑市不打（反正阻止牌也没用） |
| 利好 | Boss 在 `canClose` 时、落锤前 90% 打出（分成已定，多出的全归自己） |
| 独家协议 | Boss 在 `canClose` 时、若有人手牌 ≥ 3 张且总额 ≥ $10M 则 80% 先锁桌再成交 |
| 利空 | 被排除且打不出旅行牌时，对领先的 Boss 或坑过自己的人 70% 打出（总额 ≥ $12M）；倒计时里作为最后一手对领先者 / 终局阶段使用 |
| 阻止新牌 | 利好：非 Boss 且 Boss 领先或已进终局 → protect × 0.8；利空：Boss 85% 阻止；独家协议：被排除、手里还有老板 / 旅行 / 利空牌 → protect |
| 版本 | 所有 "第 10 笔 / 15 笔" 之类的阈值都改为读 `dealTiles` / `endChance`，四个版本共用同一套策略；`remainingDeals` 决定地标估值与终局判断 |

#### 桌规（换牌 / 买牌 / 兑换 / 病假，rules §10.5）

换牌类动作不结束行动，所以启发式把它们放在决策链最前面（夺回权之后）："先把手里的牌变成下一步就能打的牌，再决定打什么"。

| 桌规 | 启发式的处理 |
| --- | --- |
| 买牌 | 只在自己回合开单前（`preDeal`）、非终局、手牌 ≤ 2 张时考虑：便宜（每张 ≤ $3M）或很有钱（花费 ≤ 现金 1/8）才买；现金至少留下花费的 3 倍；1 张 60%、穷得只剩 ≤ 1 张时 40% 买 2 张。牌的期望价值有限，宁可少买 |
| 兑换 | `tradeOption`：换完**立刻能招人**才做——有夺回权且没招募牌时兑换即可立刻夺回（交出的两张 `cardKeepValue` 合计 ≤ 6 即可）；否则须存在招募目标、交出的确是废牌（合计 ≤ 2：已关闭家族的家族卡 / 定向旅行、凑不成组的单张招募）、非终局、现金 ≥ 花费 3 倍、且换后招募牌数正好够 `recruitCost`（3 / 猎头 2），70% 执行 |
| 换牌 | `swapOption`（谈判中）：成员 → 旅行——我的投资者在场、桌上有别人的同家族代表和我抢位置、我不是 Boss、未被独家协议封锁、总额 ≥ $8M、方案没用到我这一家（对手在方案里或还没方案）→ 80% 换出旅行牌，紧接着 `travelForMyInvestor` 把竞争者打飞（目标在方案中 +3 / 否则 +1，打掉后该家族只剩我 +2，目标属于 Boss +1；≥ 3 分且 85%）；旅行 → 成员——我的投资者本笔被打飞、这家又缺人（或 Boss 的最省方案 / 现方案用的是别人的）、总额 ≥ $6M → 换回成员卡补位 |
| 病假（打） | 目标由 `mostDangerous` 选：不在方案里拿钱、手牌 ≥ 3 张、`手牌×2 + 现金×0.05 + 坑过我的次数×1.5` 最高者。三处使用：开单前准备开 ≥ $10M 的单且想开时 60%（`preDeal`）；非 Boss 在方案里有钱时以 `protect × 0.7` 概率放倒搅局者；Boss 在 `canClose` 落锤前 70%（在独家协议之后、利好之前） |
| 病假（阻止） | 只在目标是我时考虑：手里有能打的牌（老板 / 旅行 / 利空 / 病假 / 家族卡，或 ≥ 2 张招募）且这单与我有关（我没分成，或总额 ≥ $12M）→ `protect` 概率阻止 |
| 病假中 | 合法动作里已没有出牌 / 换牌选项，启发式自然退化为喊话 / 报价 / 跳过 / 应答；`hasTeeth` 评估对手威胁时把病假中的人视为无牙 |

仿真参考（`SIM_MODE=heuristic npm run simulate -- 160`，桌规按版本默认）：每局换牌 0.3–1.7 次、买牌 1–8 次、兑换 0–0.5 次、病假生效 0.8–2.7 次；银行收入完整 $3.8M / 扩张 $8.6M / 马拉松 $37M，占总成交额约 3–5%。

### 3.3 台词

台词来自**每位人物自己的台词库**（`ai/lines.ts`）：8 位人物 × 全部情境（报价、压价、还价、应答同意 / 拒绝、成交、放弃、搅局、阻止、放狠话、被排除、封口费……），每个主情境 ≥ 3 句、点缀情境 ≥ 2 句，每句 ≤ 40 字，占位符（金额、对方姓氏等）渲染后不残留。
`heuristicSpeech(state, action)` / `quoteLine` 经 `pickLine(...)` 挑句：
- **确定性**：只用 `stateRand(state, salt)`（由 `stateVersion` 与 `state.rng` 派生，不碰 `Math.random`），同一状态同一句，仿真与重放不变；
- **去重**：避开这位玩家最近说过的话（`recentSpeechesOf`），库里的句子全说过才放回来重复；
- **有区别**：人物之间台词重合度极低（测试里断言），同一局面不同人物一定说不同的话。
LLM 没给 `speech`、或熔断期间走启发式时，说的都是这套人物台词，所以降级时不会"换了个人"。

### 3.4 人际记忆（`ai/relations.ts`）

```ts
relationsOf(state, fromId): Record<toId, Relation>     // fromId 眼中每个人
relationsToward(state, targetId): Record<fromId, Relation>  // 每个人眼中的 targetId（relationsOf 的转置）
interface Relation { score: -2 | -1 | 0 | 1 | 2; reasons: string[] }
```

纯函数，只读 `dealHistory` 与当前谈判，**不存任何状态**（同一状态永远同一结果，不改状态）。记仇：搅过我当 Boss 的单、有份却被排除在外、本笔方案绕开我；好感：当 Boss 时分过我钱。越久远越淡（按交易笔数衰减）。`reasons` 是面向玩家的中文短句（如"上次搅了你的单"），LLM 提示词的"人际"一栏直接用它；启发式用 `score` 调整让步、搅局、阻止的概率与 Boss 的分成。

### 3.5 桌风（`ai/tableStyle.ts`）

`LLMConfig.tableStyle`：`friendly`（友好）/ `business`（商战，默认，倍率全为 1）/ `ruthless`（冷血）。`STYLE_PARAMS` 给启发式参数乘一组倍率：报价 `ask`、应答阈值 `accept`、搅局 `disrupt`、压价 `haggle`、Boss 自留底线 `keep`、记仇 `grudge`、让步意愿 `flex`、放狠话 `bluff`；LLM 侧由 `toneOf(style)` 写进 system 的"今晚的桌风"。桌风只来自配置（浏览器里每局开始 `reset()` 时读一次，局中改配置下一局生效；仿真用 `SIM_STYLE`），**不入存档、不影响规则与重放**——日志里记的是已做出的动作。

### 3.6 可被利用的行为的修补

- AI 当 Boss 有**人物化的自留底线**（`bossFloor`：`floor × 桌风.keep`，领先且可能终局时放得很低只求成交）：唯一代表持有者开天价时，Boss 宁可压价 / 放话 / 放弃，不会照单全付；
- 被问方的让步随**轮次与关系**变化（`roundBias`、`flex`、对 Boss 的 `score`）：同一个人不会每轮都给出同一个价，也不会被"一直喊同一句"磨到底；
- 压价试探比例按人物 `squeeze` 走，不再是固定七折。

## 4. LLM 客户端（`ai/llmClient.ts`）

| 配置 | 说明 |
| --- | --- |
| `baseUrl / apiKey / model` | 任意 OpenAI 兼容 `chat/completions` 接口（DeepSeek、OpenAI、Ollama、vLLM…） |
| `temperature` | 默认 0.5（角色需要一点即兴——台词、试探、偶尔的冒险；再高会明显增加选到不存在编号的概率）；重试固定 0 |
| `timeoutSecs` | 默认 30；thinking 模型建议调到 60 以上（或用 `extraBodyJson` 关思考）。超时后本次决策降级为启发式；连续超时 / 失败会触发熔断（§6.3） |
| `decisionScope` | `critical`（默认，只有关键决策请求 LLM）/ `all`（凡有选择的决策都请求），见 §6.1 |
| `tableStyle` | 桌风 `friendly` / `business`（默认）/ `ruthless`，见 §3.5；每局开始时读取 |
| `extraBodyJson` | JSON 对象，顶层字段合并进请求体（可覆盖 `max_tokens` / `response_format` 等；`messages` 不可覆盖）。用于 DeepSeek `{"thinking":{"type":"disabled"}}`、Qwen `{"enable_thinking":false}`、OpenAI `{"reasoning_effort":"low"}` 等 |
| `aiSpeed` | 电脑行动前的停顿档位（fast / normal / slow），按 `{negotiation, reaction, quiet}` 三档配置（`AI_SPEED_DELAYS_MS`：快 200/60/30、中 600/200/100、慢 1500/500/300 ms）；只影响观感，规则见 §6.2 |

- 每次调用记录到内存环形日志（最近 40 条：用途、模型、耗时、请求 / 响应预览），设置面板可查看。策略层的事件也进同一份日志并带 `tag`：`fallback`（本次改用内置策略）、`breaker`（熔断，暂停调用）、`recover`（已恢复）。
- 当 `content` 为空而 `reasoning_content` 存在（thinking 模型输出被截断）时取后者，解析层再从中提取 JSON。
- 若接口不支持 `response_format: json_object`（400），自动去掉该字段重试一次。
- 轮到别人后，上一次未完成的请求通过 `AbortSignal` 取消。

## 5. 信息边界

电脑玩家与人类看到的信息相同：公开的投资者归属、桌面代表、报价、方案、现金、他人的**手牌张数**。
LLM 提示词只包含自己的手牌，不包含其他人的手牌内容（`tests/llm.test.ts` 断言）；启发式策略同样只读公开信息与自己的手牌。
反应窗口依次询问所有玩家，谁持有阻止牌不会通过"是否被询问"或"放行时说了什么"暴露；界面在反应窗口与成交倒计时里同样不显示别人谁在行动 / 思考（见 [architecture.md §7.1](./architecture.md)）。

## 6. 混合策略与运行时（`ai/aiPolicy.ts`、`ai/pacing.ts`、`ai/breaker.ts`）

### 6.1 决策分级：只在值得的地方问 LLM（`ai/decisionTier.ts`）

一笔交易里电脑要做十几二十次选择，大多是机械的。`createAiPolicy` 先算出启发式动作 `h`，再由 `decisionTier(state, actor, legal, h)` 分级：

| 级别 | 决策 | 处理 |
| --- | --- | --- |
| `trivial` | 只有一个合法动作；放标记 / 自己回合开单 / 手牌超限；**反应窗口永远如此**；与这一笔无关的旁观者；非 Boss 想放行 / 跳过；Boss 只想收口成交（`CLOSE_DEAL`）或过 | 直接用 `h`（动作与台词都来自人物参数与台词库），不请求 |
| `critical` | 报价 / 喊话；Boss 提案、出牌、放弃；应答方案；出影响牌（旅行 / 老板 / 招募 / 利空…，含成交倒计时里）；封口费 | 请求 LLM；失败回退 `h` |

"想动手才问"：非 Boss 与倒计时里，只有 `h` 本身想出手（不是 `PASS` / `PASS_CLOSING`）才请教 LLM——让它定夺并配台词。反应窗口之所以永远 trivial，是因为"有没有阻止牌"不能从"想了多久"看出来。

设置项"LLM 决策范围"（`decisionScope`）：`critical`（默认）只按上表；`all` 则凡 `legal.length > 1` 都请求（`wantsLLM`）。唯一选项永远不请求，未启用 / 缺 Key 也不请求。

**调用量估算**（`h` 驱动的 60 局、3–6 人 × 四个变体，共 1240 笔交易；"旧版" = 凡有选择的电脑决策都问一次，含反应窗口 / 倒计时 / 放标记）：

| | 总请求 | 每局 | 每笔交易 |
| --- | ---: | ---: | ---: |
| 旧版（每个有选择的决策） | 18130 | 302 | 14.6 |
| 新版（关键决策） | 8206 | 137 | 6.6 |

降幅约 55%，并且被省掉的几乎都是最"无聊"的决策，台词反而因为走人物台词库更有个性。每笔交易剩下的请求主要是报价 / 喊话（≈2.4）、Boss 提案（≈1.6）与应答；这些是玩家真正会感受到"AI 在想事情"的地方。

### 6.2 节奏（`ai/pacing.ts`）与 `skipWait()`

- **停顿与决策并行**：`GameSession.runAI` 同时开始"拟人停顿"和 `policy.decide`，实际等待 = `max(停顿, 决策)`，而不是两者相加；`setThinking` 在决策一开始就亮。
- **`skipWait()`**：立即结束**当前**这次停顿（对 AI 行动前的停顿与自动放行的停顿都有效），**决策仍然要完成**（LLM 没回来就等它）；没有停顿可跳时无副作用；只影响这一次，不留痕、不进日志。
- **`paceFor(speed, state, actorId, legal)`**（`browserEnv.defaultDelayFor` 使用）：
  - 反应窗口 / 成交倒计时：停顿只由"窗口里的第几位"决定（`windowStepDelay`：第一位全额、之后逐位减半、不低于 30ms），**与手牌、合法动作个数完全无关**；5 位 AI 连续放行总时长 ≲ 2.4 × 基准（中档 ≈ 400ms，旧版 5×400 = 2000ms）。测试里构造"有阻止牌 / 没有"的两份局面，断言停顿逐档相等。
  - 唯一合法动作、与这一笔无关的旁观者（只看公开信息：没有相关家族、没报过价，不看手牌）：用很短的 `quiet` 档；
  - 其余（Boss、相关方的谈判与应答）：`negotiation` 档。

### 6.3 熔断与运行状态（`ai/breaker.ts`、`ai/aiStatus.ts`）

`CircuitBreaker` 是带可注入时钟的纯状态机，`AiHealth` 在其上加上中文原因与回调：

```
ok ──(偶发失败)──▶ degraded ──(连续成功 3 次)──▶ ok
 │                    │
 └── 连续失败 3 次或连续超时 2 次 ──▶ down（熔断：不再请求，全部走启发式）
down ──(冷却 30s 或已跳过 8 次决策)──▶ 放行一次"探测"请求
         探测成功 → degraded；探测失败 → 重新熔断（冷却翻倍，封顶 120s）
```

只有真正的失败才计入：超时、网络 / 接口错误、回复无法解析或动作不合法；**被取消（轮到别人 / 会话销毁）不算失败**。

`AiRuntimeStatus`（`ai/aiStatus.ts`，对外语义）：

| 字段 | 含义 |
| --- | --- |
| `llmEnabled` | 当前配置下 LLM 是否可用（已启用且有 Key） |
| `health` | `ok` 正常 / `degraded` 近期有失败、仍在请求 / `down` 熔断中，全部用内置策略 |
| `lastFallbackReason` | 最近一次回退的**短中文**原因（如"LLM 响应超时，本次改用内置策略"、"LLM 暂停调用（连续失败），暂用内置策略，稍后自动重试"）；无则 `null` |
| `fallbackCount` | 本局累计回退次数（熔断期间的跳过也算） |

通道：`AiHealth` 实现 `AiStatusSource {get, subscribe, reset?}`；`createBrowserEnv()` 返回 `aiStatus`，`createSession` 透传给 `GameSession`；会话构造时先 `reset()`（计数清零，熔断器**重新装填**但不丢"当前是否在熔断"的事实——整个页面共用一个 runtime，熔断状态跨局保留）、写入 `snapshot.ai`，之后每次状态变化推送并通知订阅者，销毁即退订。没有状态源时 `snapshot.ai` 恒为 `IDLE_AI_STATUS`。ai 层不依赖 game 层。

降级期间说的话来自人物台词库，动作来自启发式（同一座位仍是同一个人），玩家几乎看不出"换人"。

### 6.4 设置面板（`components/SettingsPanel.tsx`）

保留原有项（启用 / Base URL / Key / 模型 / 温度 / 超时 / 自定义请求体 / AI 节奏 / 测试连接 / 调用日志），新增：**LLM 决策范围**、**桌风**（与开局页同一份 `tableStyle` 配置，下一局生效）、超时与熔断的说明文字；调用日志里回退 / 熔断 / 恢复事件带标签单独标出。

## 7. 平衡与验证口径

- **LLM 请求量**：见 §6.1。
- **测试**：`tests/ai.test.ts` 覆盖熔断状态机、`AiHealth`、停顿与手牌无关、会话并行与 `skipWait`、`snapshot.ai` 通道、人际记忆推导、台词库（数量 / 长度 / 去重 / 人物差异 / 确定性）、人物与桌风的行为差异、AI Boss 不被按头要价、决策分级与路由（0 / 1 次请求、`all` 范围、失败熔断、取消不计）、整局 LLM 一直失败仍可重放、提示词转义；`tests/llm.test.ts` 覆盖解析与长度上限。
